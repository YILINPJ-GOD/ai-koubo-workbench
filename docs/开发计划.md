# 开发计划 — AI口播工作台 v1

> 依据：`PD.md`（2026-10-03 已确认）。本计划将 PD.md 的 11 项必做功能和 24 条验收标准（下文以 A1~A24 指代）拆解为 8 个可执行里程碑。每完成一个里程碑，用户在浏览器实际操作验收后再进入下一个。

---

## 一、技术选型（已定，不再讨论）

| 层 | 选择 | 理由 |
|---|---|---|
| 后端 | Python 3.11 + FastAPI + Uvicorn | 智谱官方 SDK 是 Python 优先；抓取生态（httpx/feedparser/trafilatura）成熟；单机部署简单 |
| 数据库 | SQLite 单文件（`data/workbench.db`）+ 原生 sqlite3 + schema.sql | 满足 PD.md 第 7 节"单文件可备份"；无迁移工具负担 |
| AI | 智谱 SDK（zhipuai），模型默认 `glm-4-flash`，统一封装 `llm.py`（重试 + JSON 修复解析） | 用户已有 key；摘要/聚合/写稿/拆解全部走同一封装 |
| 前端 | React 18 + Vite + Tailwind CSS + TanStack Query + react-router | 工作台交互多（tab/勾选/复制/轮询），SPA 体验；构建产物由 FastAPI 静态托管，运行时无需 Node |
| 长任务 | 内存任务表 + 前端轮询（刷新流水线、素材包生成、文案拆解） | 单用户无需消息队列；支撑 A4/A14/A19 的进度与"离开页面不中断" |
| 文字卡片配图 | Pillow 绘制（Windows 自带微软雅黑） | 零浏览器依赖，风格可控（深色大字抖音风） |
| 启动 | `启动.bat`：起 Uvicorn → 自动开浏览器 `http://127.0.0.1:8787` | 双击即用，满足 A1 |

**项目结构**：

```
口播/
├── PD.md  docs/  data/            # 文档与运行时数据（data/不入库）
├── app/
│   ├── main.py                    # FastAPI 入口、静态托管、启动时自动备份
│   ├── config.py  db.py  schema.sql  llm.py
│   ├── pipeline/                  # fetchers/(6源适配器) extract.py summarize.py cluster.py score.py run.py
│   ├── services/                  # feed.py hotspots.py packs.py styles.py cardgen.py backup.py jobs.py
│   └── api/                       # 路由: system settings feed hotspots packs styles backup
├── web/                           # React 源码；pages/{Today,Hotspots,HotspotDetail,Feed,Styles,Settings}
└── 启动.bat  requirements.txt
```

## 二、数据模型与核心接口（开发前定死）

**表**（schema.sql）：
- `sources`：key、名称、类型（official/media/overseas/trending）、启用开关
- `items`：标题、url、摘要、中文翻译摘要（海外）、分类、原文图URL、抓取时间、已读/收藏、event_id
- `hotspots`：事件标题、为什么值得讲、切入角度、建议时长、热度分、状态（pending/packed/shot）、日期、cover、sequel_of
- `packs`：hotspot_id、三档口播稿/字幕(JSON)、配图候选+选用(JSON)、发布文案(JSON)、风险报告(JSON)、style_id、生成时间
- `styles`：模板名、原文、拆解五件套(JSON)、已用次数、创建时间
- `fetch_runs`：每次刷新各源状态与耗时（辅助诊断的健康记录）

**主要接口**：
```
POST /api/refresh          GET /api/refresh/status        # 刷新流水线（任务）
GET  /api/today                                           # 首页聚合：必做+备选+漏斗
GET  /api/feed    PATCH /api/items/{id}    POST /api/feed/read-all
GET  /api/hotspots    GET /api/hotspots/{id}    POST /api/hotspots/{id}/mark-shot
POST /api/hotspots/{id}/pack      GET /api/packs/{id}      # 生成（任务）与读取
PUT  /api/packs/{id}/images       POST /api/packs/{id}/regenerate
GET/POST /api/styles/teardown    PUT/DELETE /api/styles/{id}
GET/PUT /api/settings            POST /api/settings/test
POST /api/backup/export  POST /api/backup/import  POST /api/data/clear
GET  /api/health                                          # 每源健康记录
```

## 三、里程碑计划（共 8 个，约 7~9 个工作日当量）

### M0 项目骨架与启动（0.5 天）
- 初始化 venv、requirements.txt、FastAPI 骨架、schema.sql 建表、config.json 读写
- React + Vite + Tailwind 脚手架；五个页面的导航壳（空页面）
- `启动.bat`（含 `chcp 65001` 处理中文）与开发用 `dev.bat`
- **完成标准**：双击启动，浏览器打开首页，五个 tab 可切换（A1 的壳）

### M1 设置页与 LLM 地基（0.5 天）⚠️ 需要用户提供智谱 key
- `llm.py`：统一封装（调用、超时、重试、JSON 输出修复解析），是后续所有 AI 功能的地基
- 设置页：key 脱敏显示与保存、「测试连接」、模型选择、6 源开关、写稿偏好（风格+补充要求）
- **完成标准**：A2、A3

### M2 抓取流水线与资讯流水页（1.5 天）
1. **源可用性验证（先做，半天内出结论）**：逐一实测 6 源可返回数据——官方源走公司博客 RSS + RSSHub 公共实例兜底（X 官方账号直连无 API，属已知风险，见第五节）；机器之心/量子位 RSS；微博热搜、百度热搜接口；Hacker News 用 Algolia API。不可用的源当场定替代或降级，**结论回写 PD.md 第 5.5 节源清单**
2. fetchers/ 六个适配器（统一返回 Item 草稿；单源异常不中断，状态记入 fetch_runs）
3. extract.py：正文抽取（trafilatura）+ 原文配图提取（og:image / 正文 img）
4. summarize.py：AI 一句话摘要 + 分类 + 海外条目中文翻译
5. 去重：URL 去重 + 标题相似度合并
6. 全局刷新：任务化（进度 x/6 源）+ toast 汇报；feed 页完整交互（展开/已读/筛选/搜索/全部已读/收藏/跳原文）；辅助诊断的就地红字与重试
- **完成标准**：A4、A5、A7、A8、A9（A6 属 M3 聚合）

### M3 事件聚合、热点库与首页（1 天）
1. cluster.py：每次刷新后将新条目交 LLM 聚合成事件（标题/为什么值得讲/切入角度/建议时长/热度分），同事件多来源合并并计独立来源数；**将近期已拍/已出素材的历史热点标题一并送入判断**：老话题不重复硬推、后续进展标 sequel_of（A12）
2. score.py：按"大模型/AI产品优先 + 热度 + 时效"打分，产出今日必做 0~3 与备选；无达标者时生成"没有值得做的"理由
3. 热点库页：状态流、来源确认数、按日期折叠的历史；首页：必做卡、备选折叠、漏斗行、空状态、首次引导
- **完成标准**：A6、A10、A11、A12、A13

### M4 素材包工作台（1.5 天）
1. packs.py 生成服务：一次 LLM 产出三档口播稿（字数硬约束，超限自动重试）+ 三档分镜字幕（金句加粗）+ 发布文案（标题×3/话题标签/封面大字）+ 风险词标注（绝对化用语词表 + LLM 复查）与自查清单；若指定 style_id 则注入模板结构并加套用标注；若为续集则自动带"上回说到"衔接句
2. cardgen.py：Pillow 生成文字要点卡片（深色大字抖音风，1~3 张候选）
3. 任务化 + 轮询：生成期间可离开页面，完成 toast（A19）
4. 工作台 UI：左事件区（理由/时间线/来源列表✓/角度/📌续集）/右素材区（档位联动、口播稿+字幕双栏、复制/复制整包/重新生成、配图候选勾选/大图预览/下载、发布文案区、安全检查区、「标为已拍」）
- **完成标准**：A14、A15、A16、A17、A18、A19

### M5 拆解库（0.5~1 天）
1. styles.py：粘贴文案 → LLM 拆解五件套（钩子/结构骨架/节奏/金句/CTA）→ 预览确认 → 存模板；编辑、删除二次确认、已用次数
2. 拆解库页 + 工作台风格选择器（默认人设 | 模板列表）+「套用写一条」
3. **边界校验**：套用生成的稿件与原文做相似度抽查，杜绝连续照搬（A21 后半句）
- **完成标准**：A20、A21

### M6 备份恢复与数据保护（0.5 天）
1. backup.py：启动自动备份滚动保留 7 份（main.py 挂钩）；导出 zip（db+config+images）；导入 zip（先自动备份当前→覆盖→提示重启）；清空数据强制二次确认+先备份
- **完成标准**：A22、A23、A24

### M7 真实数据联调 + 验收走查（0.5~1 天）
1. 配真实 key 跑完整一天的真实流程：刷新 → 首页 → 选热点 → 素材包 → 拆解套用
2. 按 PD.md 第 10 节 24 条逐条走查打勾；不及格项修复后复测
3. 收尾：README（启动/备份说明）、默认源实测微调
- **完成标准**：24 条全过，交付

## 四、测试策略（轻量但覆盖要害）

- **pytest 单测**（M2/M3 期间持续补）：去重与相似合并、事件聚类解析、字数硬约束重试、风险词表匹配、备份滚动删除——这些是纯逻辑，必须机器测
- **抓取适配器**：每个源留一份"真实响应样本"fixture，接口变动时可离线回归
- **验收**：以 PD.md 第 10 节为唯一清单，M7 与用户共同走查

## 五、风险与预案（开工前已知）

| 风险 | 影响 | 预案 |
|---|---|---|
| X（推特）官方账号无免费 API，直连抓不到 | "官方源"缺一角 | 首选公司官方博客 RSS；X 走 RSSHub 公共实例尽力而为；M2 源验证时定论，不可用则降级并在设置页标注 |
| 微博/百度热搜接口非官方，可能变动 | 热点发现变弱 | 适配器隔离 + fixture 回归；失效时该源标红跳过，不阻塞其他源 |
| LLM JSON 输出偶发不合法 | 管道中断 | llm.py 统一做 JSON 修复 + 重试；连续失败进辅助诊断报错 |
| 字数/格式不符合口播稿要求 | A15 不过 | 生成时硬校验字数区间，超限自动重试一次，仍超限标注提示 |
| Windows 中文路径/编码 | 启动报错 | bat 用 chcp 65001；路径统一 UTF-8 处理（M0 验证） |
| 单条刷新全流程耗时长 | 等待焦虑 | 刷新与生成全任务化 + 进度可见；本就设计为"可离开页面" |
